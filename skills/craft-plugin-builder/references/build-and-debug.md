# Development, packaging and debugging

Prerequisite: Node/npm locally; Windows Craft >= 5.1.018.1021.
From the copied template's plugin directory:

```powershell
npm install
npm run dev
```

The default command installs a thin Node launcher that uses the developer's
system Node and source tree. It does not bundle and is not distributable.
Restart Craft to load it. Close Craft before replacing an existing installation.
After code changes, rerun dev and restart Craft; reopen the PI to inspect edits.
Always ask the user to test text/colors, resizing, and multiple widget instances.
Explicitly label this as a development version and ask for confirmation before
the production build. Explain that it is not yet a shareable installer.
Only after confirmation or an explicit release request:

```powershell
npm run build
```

Build runs ncc and installs all emitted output files, including extra assets.
The npm postbuild hook then generates `release/<plugin-id>.mPanelPlugin` in
the project root. It contains ZIP bytes with manifest.json directly at root,
not a same-named wrapper folder. A production request requires build AND
installation AND this installer. Return its absolute file link and actual
install path, say it can be shared, and provide
https://space.mirabox.net/contentUpload for publishing. See `packaging.md`.
For automated compilation without installing, use npm run bundle.
For native graphics packages, validate binaries against target OS/architecture
and Craft's actual Node runtime; ncc does not make native modules portable.

Both Node and Vue templates include a self-contained `craft-paths.cjs` helper
used by their dev/build installers. Windows plugin-root precedence:

1. `CRAFT_PLUGINS_DIR`: explicit plugin-root override, including isolated tests.
2. `%APPDATA%/HotSpot/configuration.ini`: read `[DeviceTypeDownNum]`, decode the
   key `MiraBox%20Craft` (also accepts `MiraBox Craft`), and append `plugins`
   to its value. The value is a data directory, not the plugins directory.
3. If the file/key is missing or empty, use
   `%APPDATA%/HotSpot/MiraBox Craft/plugins`.

For example, `MiraBox%20Craft=F:/CraftData/MiraBox Craft` installs under
`F:/CraftData/MiraBox Craft/plugins`. Paths containing spaces, Chinese text,
and quoted values are supported, as are UTF-8 BOM and UTF-16LE BOM INI files.
Do not URL-decode the path value: literal `%` sequences in directory names
must be preserved. Invalid relative paths or unreadable configuration files
stop installation instead of silently falling back to the wrong directory.
The override is already the plugins directory; do not append `plugins` to it.
The helper reads configuration on each install without changing it. Non-Windows
targets must provide a verified `CRAFT_PLUGINS_DIR` explicitly.

The installed name in the Node template is derived from the first action UUID:
com.mirabox.streamdock.<name>.mPanelPlugin. Keep all UUID prefixes consistent.
The installer rejects overlapping source/target paths and does not delete
directories or kill host processes.

Do not reuse Dock's keepalive handoff, 50-restart limit, or manifest hot-reload
version claims: these have not been established for Craft.
The production bundle, not the dev launcher or node_modules directory, belongs
in the distributable .mPanelPlugin folder.

Backend logs: plugin/log/craft.log in the source or production installation.
PI/webview debugging: http://127.0.0.1:23518; it does not debug Node itself.
A missing action usually means UUID mismatch, unsupported Craft version,
incorrect CodePath/Nodejs, invalid manifest, or failure to restart Craft.

The ZIP files already in the repository are legacy artifacts and are not
regenerated by these scripts. Copy the directory template, not an old ZIP.
